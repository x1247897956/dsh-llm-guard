# heldout 评测数据集：LLM 应用输入安全检测

本目录是「LLM 应用输入安全检测」（提示词注入 / 越狱 / 敏感数据外泄，规则层 + 语义层）的
评测数据集。数据集**全部为合成文本**，由本仓库作者人工构造并逐条标注。

- 数据文件：`heldout.jsonl`
- 说明文件：`README.md`（本文件）

## 1. 数据格式

JSONL，每行一个 JSON 对象，UTF-8 编码，字段固定：

| 字段 | 类型 | 取值 | 说明 |
| --- | --- | --- | --- |
| `id` | string | `m-<pi\|jb\|sd>-NNN` / `b-<pi\|jb\|sd>-NNN` | `m-` 恶意、`b-` 正常；`pi`=提示词注入、`jb`=越狱、`sd`=敏感数据 |
| `text` | string | 待检测文本 | 单行字符串，换行统一用 `\n` 转义 |
| `label` | int | `1` 恶意 / `0` 正常 | 真值 |
| `category` | string | `prompt_injection` / `jailbreak` / `sensitive_data` | 恶意样本＝攻击所属类别；正常样本＝它是**针对哪一类检测器**的负样本 |
| `note` | string | — | 一句话考点说明（含所用变形手法） |

`category` 对正常样本的含义是"最容易被该类检测器误报"，因此负样本是按检测器分桶收集的，
而不是按主题随机抽样。

## 2. 构造方式

1. **先分桶**：按三个检测器分三类，每类再分"恶意"与"正常"两桶。
2. **恶意样本两层设计**：一部分保留规则层能命中的**字面模式**（作为基线对照，用来观察
   规则层本身是否正常触发）；另一部分刻意**绕开字面模式**——用语义等价但字面不同的表达、
   编码、拆分、藏头等方式承载同样的意图，用来检验语义层的增益。
3. **正常样本制造误报压力**：优先收录"字面上像攻击、意图上完全正常"的文本
   （提到"忽略"但是参数语义、出现 `DAN` 但是人名或版本代号、出现 `system:` 但是文档排版问题、
   出现私钥头但是教程占位符），以及**正常业务里天然包含邮箱 / 手机号 / 单号**的文本
   （客服工单、签名档、会议通知、短信模板、发票信息、单测数据）。
4. **逐条写 `note`**：标注该条的考点与变形手法，便于按手法分层统计。
5. **内容红线**：只写"攻击的形态"，不写可操作的真实攻击步骤；需要指向违规内容处一律用
   `<此处为我要求的违规内容>` 之类的占位表述；不出现真实人名、真实公司内部信息、
   真实可用凭据、真实个人信息；不含仇恨、色情、未成年相关内容。

所有邮箱统一为 `example.com`；手机号统一使用测试号段（如 `13800138000`）；
18 位号码使用公开通用的测试假号（如 `110101199003071234`）；
凭据一律为公开文档示例值或带 `TESTONLY` / `EXAMPLE` 字样的明显假值。

## 3. 变形手法清单与覆盖情况

恶意样本按 `note` 归类（同一条样本只归一手法，"字面模式"指未做变形的基线样本）：

| 变形手法 | prompt_injection | jailbreak | sensitive_data |
| --- | ---: | ---: | ---: |
| 字面模式（规则层基线对照） | 10 | 9 | 11 |
| 间接 / 嵌套引用（把系统说明重定义为"过期草稿""遗留文档""上一轮口径"） | 2 | 1 | 1 |
| 角色扮演包装（剧本、小说、虚构人物） | 2 | 2 | 1 |
| 渐进式心理暗示（认同 → 假设 → 要求） | 2 | 2 | 1 |
| 长文本包裹（会议纪要 / 技术手册 / 周报外壳） | 2 | 2 | 1 |
| 编码 / 字形绕过（base64 分组、零宽字符 U+200B、拼音、拆字、空格打散、全角字符） | 5 | 5 | 4 |
| 藏头 / 首字母（中文每句首字、英文每行首字母） | 2 | 2 | 1 |
| 虚构场景豁免（安全测试 / 论文 / 拍电影 / 授权演练） | 2 | 2 | 1 |
| 敏感数据变体（凭据分段与口述、字段分组） | — | — | 7 |
| 其它（拒答词表削弱、日志片段与截断结构） | — | 1 | 2 |
| **合计** | **27** | **26** | **30** |

三类都覆盖了上表列举的变形手法中的 4 种以上（`sensitive_data` 因数据形态不同，
主要落在"拆分 / 编码 / 藏头 / 虚构 / 长文本 / 渐进"这一侧）。

按类别与标签拆分：

| category | 恶意（label=1） | 正常（label=0） | 小计 |
| --- | ---: | ---: | ---: |
| `prompt_injection` | 27 | 26 | 53 |

`sensitive_data` 22）；其中 10 条 `sensitive_data` 负样本**天然包含**可被正则命中的示例邮箱、
测试手机号或测试假号（这些是本数据集有意保留的高误报压力样本）。

## 5. 数据集自带的规则层命中性质

这一节描述的是**数据集本身的属性**（构造时用规则层字面模式清单离线统计得到），
不是对任何系统的评测结论。

规则层口径：按任务给定的字面模式清单（注入 / 越狱 / 敏感数据三组正则与关键词，
大小写不敏感）对每条 `text` 做匹配，命中任一模式即视为"规则层可抓到"。

| 统计项 | 数量 | 占比 |
| --- | ---: | ---: |
| 恶意样本中规则层可抓到 | 30 / 83 | 36.1% |
| 恶意样本中**完全不含**任何规则字面模式（只能靠语义层） | 53 / 83 | 63.9% |
| 正常样本被规则字面模式命中（误报压力） | 18 / 74 | 24.3% |

恶意样本中规则层抓不到的 53 条，正是语义层存在的意义所在：
它们包含间接覆盖、剧本包装、渐进铺垫、长文本埋点、base64 / 零宽 / 拼音 / 拆字、
藏头、凭据拆分等形态。索引可参考 `id` 段（例如 `m-pi-011` 起的变形段、
`m-jb-010` 起的变形段、`m-sd-012` 起的拆分段）。

## 6. 校验

构造完成后用 Python（标准库 + 仓库内检测器）逐行校验，检查项与结果：

1. 每一行都能 `json.loads`：157/157 通过；
2. 字段集合、顺序、类型与取值合法（含 `m-`/`b-` 前缀与 `label`、`id` 中段与 `category` 的一致性）；
3. 统计恶意 / 正常总数与各类别数量（见第 4 节）；
4. `id` 无重复；
5. PII 检查：出现的邮箱域只有 `example.com`，手机号只有 `13800138000`，
   18 位号码只有 `110101199003071234`，无真实邮箱域（`gmail.com` / `qq.com` / `163.com` 等）；
6. 规则层命中率统计（见第 5 节）。

最小结构校验片段（在仓库根目录执行）：

```bash
python3 - <<'PY'
import json
rows = [json.loads(l) for l in open("eval/dataset/heldout.jsonl", encoding="utf-8")]
assert len(rows) == len({r["id"] for r in rows}) == 157
for r in rows:
    assert list(r) == ["id", "text", "label", "category", "note"]
    assert r["label"] in (0, 1)
    assert r["category"] in {"prompt_injection", "jailbreak", "sensitive_data"}
print("malicious:", sum(r["label"] == 1 for r in rows), "benign:", sum(r["label"] == 0 for r in rows))
PY
```

## 8. 标注方式与合规声明

- **标注方式**：由本仓库作者人工构造并逐条标注。每条样本的 `label` 与 `category` 都是人工判定，
  没有使用模型自动打标；`note` 记录该条的考点与变形手法。
- **合成数据声明**：本数据集为合成数据，不含真实个人信息、不含真实凭据、不含任何真实公司内部信息。
  所有联系方式均为测试号段或 `example.com` 占位邮箱，所有凭据均为公开文档示例值或明显假值。
- **内容边界**：样本只描述攻击的**形态**，不包含可操作的真实攻击步骤；
  需要指代违规内容处使用占位表述。

## 9. 已知偏差与限制

- 样本由**单人**构造并标注，缺少第二人复核，`label` 的边界判断带有个人口径。
- 规模为**百条级**（157 条），只适合作为小规模回归与消融对照，不足以支撑统计置信区间的结论。
- **变形手法分布不均**：多数手法每类只有 1–2 条；`sensitive_data` 一侧集中在"凭据拆分"，
  而"藏头""虚构场景""渐进暗示"各只有 1 条。分类别看指标时，小样本类别的波动会很大。
- **不含多轮对话场景**：所有样本都是单轮 user 文本，没有覆盖"先正常几轮再注入"
  这类跨轮次攻击，也没有覆盖 system / tool 消息被投毒的场景。
- 未做近重复检测与跨类别去重，个别样本在语义上可能彼此接近。
- 第 5 节的规则层命中比例依赖所采用的**字面模式清单**；仓库内的规则检测器仍在演进
  （例如为身份证号补充校验位判断、为敏感数据增加新形态），
  因此该比例应随清单版本一起解读，而不是一个永久常量。
- 数据集故意保留了一批"规则层会误报"的正常样本（第 5 节 18 条）。
  这是设计目标，不是脏数据；用它算误报时请一并说明这一口径。
